# FINAL 実装スペック — QUALIA メンバープレゼンページ（採用案=案Bハイブリッド）

> **Round 4 の性質: 採用案の統合のみ。設計方向は新規に作らない。** Round3 で PASS した 案B（ハブ＆ダッシュボード型）に 案A の 48px 薄型章扉を取り込んだハイブリッドを、実装者がこのファイル単体で作れる粒度に一本化したもの。設計本体（13セクション構成・配色・タイポ・ロック/準備中UX）は Round3 から変更しない。

## 0. 採用方針（全体構造）

紹介者が見込み客に 1 対 1 で対面で見せる、紺×金（明るめ）の長尺 1 枚プレゼンツール。スマホ縦が主・iPad 対応。

**構造（案Bハイブリッド）:**
1. **ヒーロー** → 紺グラデ全面・QUALIA ワードマーク＋アクロスティック＋主役石井諒の小丸写真。下端に「メニューへ↓」。
2. **ハブ（hero 直下・本案の核）** → 13セクションのタイルグリッド。タイルタップで該当セクションへ smooth scroll。`Genius` 型タイルメニュー（分岐の入口）＋ `iOS ホーム画面` 型 hub-and-spoke（別セクションへ移るには必ずハブに戻る往復）。
3. **13セクション本体** → 各セクション頭に **48px 薄型章扉（案A 型: 金1pxライン＋金章番号＋セリフ章タイトル）** ＋各セクション末尾に「ハブに戻る↑」金リンク。章扉が `IntersectionObserver` で現在地アンカーを兼ね、長尺の迷子を防止（案B の物語性の弱さを案A の章扉で補強）。
4. **右上常駐ハンバーガー** → スクロール位置を問わず常時固定。役割は「どこからでも飛べる常駐ナビ」。ハブ（通過するコンテンツ面）とは面の性質が違うため重複でなく補完。

**ハブとハンバーガーの役割分離（明文化）:**
- ハブ = コンテンツ面。冒頭に 1 回置く大きな分岐画面。スクロールで通過する。
- ハンバーガー = 常駐ナビ。右上に常時固定。現在地表示＋遠距離ジャンプ＋「ハブに戻る」を内包。

## 4. 章扉（案A 型・薄型 48px）

各 13 セクションの先頭に置く。ヒーローとハブには章扉を付けない。

- 高さ約 **48px**。
- 構成: **金 1px ライン（上）＋ 金章番号（01〜13, ラベル組 11/12px 700 0.12em）＋ セリフ章タイトル（26/32px 600 0.04em）**。
- 背景は当該セクションの地（薄地 or グラデ）。金 1px の罫の「規則性」で章を立てる（160px の重い扉は使わない＝スクロール過多回避）。
- `id="sec-01"` … `id="sec-13"` を章扉要素に付与し、`IntersectionObserver` の監視対象にする＝ハブ／ハンバーガーのアンカー先・現在地検出を兼ねる。

## 5. ハンバーガー & ハブ（挙動）

### ハンバーガー（常駐ナビ）
- 位置: 右上固定 `fixed top-4 right-4`、サイズ 44×44px。

## 8. プラン合言葉ロックの状態機械（07）

> **Round5 修正（バックエンド配線を実機に整合）。** 設計UI（locked/unlocked の見た目・文言・解除アニメ）は Round4 から不変。変更は **データ層の配線のみ**＝既存 Layer2（httpOnly 署名 Cookie）に正しく接続し直した。

### バックエンド配線（実機の確定事実に基づく）
- **照合に `app/api/password/route.js` を流用しない。** このルートは**管理者用**（`adminPassword` を `process.env.ADMIN_PASSWORD` と照合し、7日分のパスワード一覧を返す）であり、viewer の合言葉ゲートではない。誤って流用すると admin API に配線してしまう。
- **正規バックエンド = `lib/auth/layer2.js`**（実在・部品完成済み）。
  - `PLAN_COOKIE = 'qualia_plan'`（httpOnly 署名 Cookie）
  - `issuePlanToken()` … 合言葉照合成功時に発行。`exp = getJstMidnightExpiryEpoch()`＝**JST 当日 24:00 失効**（`lib/date.js`）。
  - `verifyPlanToken(value)` … 署名検証＋`exp <= nowEpoch()` で失効判定。
  - `planCookieOptions()` … httpOnly/Secure/SameSite を付与。
- **verify route は未実装**（現状 `app/api/auth/plan/` も `app/api/plan/unlock` も存在しない）。実装者は **`app/api/auth/layer1/route.js` と同型**で plan 用 verify route（例 `app/api/auth/plan/route.js`、`runtime='nodejs'`）を新設する：
  1. `clientIp(request)` ＋ `checkAndIncrement({scope:'layer2', ip, jstDate:getJstDateString(), max:10, windowMin:15})` でレート制限（`lib/ratelimit.js`、超過は **HTTP 429**）。
  2. `verifyPassword`（`lib/password.js`・JST 日替わりパス照合）で合言葉を検証。失敗は `gate.registerFailure()` ＋ **401**。
  3. 成功は `gate.registerSuccess()` ＋ `res.cookies.set(PLAN_COOKIE, await issuePlanToken(), planCookieOptions())` で **httpOnly 署名 Cookie** をセット。
- **保護動画 ID の遅延配信は Phase4 の `GET /api/plan/content`**（`verifyPlanToken` 検証後にのみ layer2 の `youtube_id` を返す。`Cache-Control: no-store`）。**07 の UI は保護 ID をビルド時に埋め込まない**。

### 状態
`locked`（初期）→ `unlocked`。unlocked の保持は **`qualia_plan` httpOnly Cookie の有無／`verifyPlanToken` の真偽** で判定する（**localStorage は使わない**）。理由: localStorage は (a) サーバ検証不能でバイパス容易、(b) 日替わり失効しない＝合言葉が毎日再ロックされる設計（`generateDailyPasswordForDate`／`exp=JST 24:00`）を破壊する。Cookie は JST 24:00 で自動失効し、翌日は再入力が必要（仕様どおり）。ハブ 07 タイルの「鍵→金チェック」表示も **Cookie の有無（または verify API 応答）で出し分ける**。

### locked 画面（要素列挙）
- (a) **上半分は通常表示**: ショート×3＋プラン概要を通常レンダリング（ショートは locked でも再生可＝「拒否」でなく「もっとある」）。
- (b) その下に **金 1px の区切り線 ＋ ハードカットのゲートブロック** で本編（ロング動画/詳細条件）を遮断。**フェード（縦グラデで徐々に隠す）は不可＝ハードカット**。本編は遮断帯の背後に **輪郭だけうっすら**（"もっとある"の予告。完全には隠さない）。
- (c) ゲートブロック中央: 鍵アイコン（直径 28px・金 1px アウトライン円・塗りなし）＋ 文言「続きは紹介者から合言葉を聞いて開けます」。
- (d) 入力 UI: **単一フィールド**（桁分割は不採用。合言葉は桁数固定でない文字列で、桁分割だと「何桁か」を漏らし威圧/緊張を生むため）。`placeholder="合言葉"`、中央寄せ、幅 `max-w-[280px]`、紺枠 1px。
- (e) 送信（解除）ボタン: フィールド直下、金アウトライン「解除する」。**画面下 1/3 の親指リーチ**に配置。
- (f) エラー文言（**赤は使わず `navy-400`**、控えめ）:
  - 1 回失敗: 「合言葉が違うようです。もう一度どうぞ」
  - 連続 3 回: 「紹介者にもう一度確認してみてください」
- (g) **試行制限の見せ方（UI 層とサーバ層を分離）**:
  - **UI 層**: 威圧を避けるため、3 回程度の失敗ではロックアウト UI を出さず、上記 (f) の連続文言を出すのみで入力は受け付け続ける（早期ロックアウトしない）。
  - **サーバ層（必ず維持）**: verify route のレート制限（`checkAndIncrement` max 10/15分→**HTTP 429**）は layer1 と同様に**常に有効**。多数回失敗で 429 に達したら、UI は初めて「しばらく時間をおいてからお試しください」を表示する。
  - 「ロックアウトしない」と断言してサーバ 429 を無効化してはならない（バイパス・総当たりを許す誤実装になる）。UI の体感とサーバの強制は別物として両立させる。

### unlocked 画面（要素列挙）
- 解除アニメ: ゲートブロックが **250ms（`ease-out`）** で解け、区切り線が消えて下半分（本編）が立ち上がる（`fade-in + translateY`）。
- 表示: ショート/ロングのタブ（選択中=金下線）＋ 各タブ内に動画 ＋ プラン比較（ショート/ロング段組）＋ 報酬条件。
- **ショートは常時開放 / ロングは解除後に表示**。
- ハブの 07 タイルの金鍵アイコンが **金チェック** に変わる（全体像として「開いた」を示す）。
- 再訪時は **`qualia_plan` httpOnly Cookie が有効な間（＝同一 JST 日内）** unlocked のまま（入力不要）。**JST 24:00 を越えると Cookie が失効し再ロック**＝翌日は新しい日替わり合言葉での再解除が必要（localStorage は使わない）。

## 9. 動画タップ再生（実装方針）

既存 `components/ui/VideoPlayer.js` は**現状 iframe を即時ロードしている**。動画多数（03/04/05/09/11/12 ＋ロング/ショート）でこれを全先読みすると初期ロードが重い。**サムネ→初回タップで iframe 生成方式に変更する。**

- **タップ前**: `<img>`（YouTube `hqdefault` or カスタムサムネ）＋ 中央に金リング内の白 Play 三角（直径 56px）＋ 左下に尺ラベル（`navy-400` キャプション組）。iframe は生成しない。
- **タップ後**: 初めて `youtube-nocookie` iframe（`autoplay=1`）に差し替える（その動画だけ。他は触られるまでサムネのまま）。
- iframe URL は既存と同パラメータを踏襲: `https://www.youtube-nocookie.com/embed/${videoId}?modestbranding=1&rel=0&showinfo=0&cc_load_policy=0&autoplay=1`。
- **全動画の iframe を先読み（eager load）しない**＝必須要件。
- ショート（09）の「音声なしミュート自動ループ」は別扱い: ミュートで自動ループ再生可（タップ不要）。ロングはタップ再生。
- 右クリック防止オーバーレイ（既存実装の `onContextMenu` 抑止）は維持。
