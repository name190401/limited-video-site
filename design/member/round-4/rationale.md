# rationale — Round 4

## このラウンドの性質
**Round4 = 採用案の統合。設計方向は新規に作らない。**

Round3 で reviewer が PASS（9 カテゴリ全 ✓）した内容のうち、推奨された **採用案＝案B ハイブリッド**（冒頭ハブタイル → 各セクションへ往復 ＋ 案A 型 48px 薄型章扉 ＋ 右上常駐ハンバーガー）を、実装者がこのフォルダ単体で作れる **1 本の実装スペック** に統合・明確化した。3 案併記（A/B/C）を畳み、採用案だけの単一仕様にした。

## 採用案の確定内容（Round3 PASS から不変）
- **構造**: 非線形ハブ（案B）＋ 物語性/現在地を補う案A の 48px 薄型章扉。`Genius`＝タイル分岐の入口、`iOS ホーム画面`＝spoke→hub 往復、`Confirmed`＝準備中予告 の 3 件が体験構造を決める load-bearing。
- **07 ロック**: 単一フィールド ＋ 上半分開放 ＋ 金1px区切り線 ＋ **ハードカットゲートブロック（フェード不可）**。エラーは `navy-400`、3 回でもロックアウトしない。`Substack` スクショの実体（ハードカットの有料ゲート）に準拠。
- **08 ボーナス数値**: 実数値を入れず **法規制確認前のプレースホルダ** のまま。
- **準備中**: `ComingSoonCard`（タイトル/担当/公開月）。グレーアウト/工事中アイコン禁止。案B はハブタイルで予告＋本体最小化。
- **動画**: サムネ → 初回タップで `youtube-nocookie` iframe 生成（全先読み禁止）。

## このラウンドで「変更していない」こと（統合・明確化のみ）
- 13 セクションの構成・各セクションの要素・配色トークン（既存 navy/gold）・タイポスケール・余白/グリッド・ロック状態機械・準備中部品仕様は **Round3 から一切変えていない**。
- 文言・数値・座標は Round3 に書かれた値をそのまま採用案向けに 1 本化しただけ。

## このラウンドで「明確化した」こと（実装可能粒度への落とし込み）
1. 3 案併記を畳み、採用案 1 本の単一スペックにした（実装者が分岐を読まなくて済む）。
2. 既存 `tailwind.config.js` の実トークン hex と `components/ui/VideoPlayer.js` の現状（iframe 即時ロード）を照合し、**動画は「サムネ→タップで iframe 生成」へ変更する必要がある** ことを実装方針として明記（現状の facade は全先読みになるため）。
3. `app/api/password/route.js` の照合ロジックを 07 で流用する旨を明記。
4. 実装後の自己照合チェックリストを FINAL_spec 末尾に追加（禁則・金運用・ロック挙動・プレースホルダ等）。

## 形容詞濫用について
FINAL_spec / references とも、banned 形容詞（高級感/洗練/モダン/美しい/直感的/シンプル/スタイリッシュ/エレガント）は使用していない。配色・構造はすべて具体トークン・具体挙動・実在参照に紐付けて記述している。

## 実装後の品質保証（次工程への申し送り）
- グローバル方針（Quality Gate）に従い、実装物は単発レビューで PASS とせず、**連続 2 ラウンド PASS** まで回す。
- 08 の数値・コピーを実投入する段階では、**最新の法規制トーン確認が別途必須**（このスペックはプレースホルダのまま）。
