# 案A: 章立てプレゼン進行型（Chapter-driven・線形）

「上から順に見せれば、そのままプレゼンの台本になる」— セクション境界を章扉にし、紹介者が指でスクロールしながら話す流れを設計。

## 案A 固有の確定判断（reviewer 指摘6a）
- **章扉は 160px ではなく『48px 金1pxライン＋金章番号＋セリフ章タイトル』の薄型に確定**。根拠: Round1 で自ら指摘した「160px×13＝スクロール過多」を解消。薄型でも IntersectionObserver で現在地アンカーを兼ねられ、迷子防止機能は失わない。章扉の"重さ"でなく"罫の規則性"で章を立てる。

## 案A ロック↔解除（07 の locked / unlocked 2 画面・要素列挙）
**locked 画面（参照: Mimo「進めば開く」）:**
- (a) 鍵アイコン: セクション中央上、直径 32px 金1pxアウトラインの円内に鍵、塗りなし。
- (b) 見出し直下に文言「このプランの詳細は、紹介者から合言葉を聞いて開けます」(Sans 15px navy-900)。
- (c) ショート動画は locked でも**再生可**（Mimo の「触りは開いている」）＝下にショート×3 サムネを通常表示。ロング/詳細だけが鍵の下。
- (d) 入力UI: **単一フィールド**(`placeholder="合言葉"`, 中央寄せ, 幅 `max-w-[280px]`, 紺枠1px)。
- (e) 解除ボタン: フィールド直下、金アウトライン「解除する」(画面下 1/3 の親指リーチ)。
- (f) エラー文言(navy-400, 赤なし): 1回失敗「合言葉が違うようです。もう一度どうぞ」/ 連続3回「紹介者にもう一度確認してみてください」(ロックアウトはしない＝威圧回避)。
- **威圧的でない根拠**: 中身を完全に隠さずショートは開放／鍵は塗りでなく細線アウトライン／文言が「拒否」でなく「紹介者と一緒に開ける」前提。
**unlocked 画面:**
- 解除アニメ: 金リングが上下に開く 250ms(`ease-out`)→鍵が消えロング/詳細が下からフェードイン。
- 表示: ショート/ロングの**タブ**(選択中=金下線)＋各タブ内に動画＋プラン比較(Peloton 型 ショート/ロング段組)。
- 再訪時は localStorage で unlocked のまま（入力不要）。

# 案B: ハブ＆ダッシュボード型（Hub & tiles・非線形）

「13枚のタイルから、その人に響くところだけ見せる」— 冒頭にメニューハブを置き、紹介者が見込み客の関心に合わせて飛び込む非線形プレゼン。

## 案B 固有の確定判断（reviewer 指摘6b：ハンバーガー形骸化の解消）
- **ハブとハンバーガーは役割を完全分離して両立**: ハブ＝**コンテンツ面**(冒頭に1回置く大きな分岐画面・スクロールで通過する)。ハンバーガー＝**常駐ナビ**(スクロール位置を問わず右上に常時固定・現在地表示＋遠距離ジャンプ＋「ハブに戻る」を内包)。両者は中身(13項目)が同じでも**面の性質(通過する vs 常駐する)が違う**ため重複でなく補完。クライアント確定の右上ハンバーガーは形骸化せず「どこからでも飛べる常駐手段」として明確な役割を持つ。

## 案B ロック↔解除（07・要素列挙）
**locked 画面（参照: Substack 「上は読める/本編は区切り線＋ゲートで遮る」）:**
- (a) ショート×3 とプラン概要の**上半分は通常表示**、その下に**金1pxの区切り線＋ゲートブロック**で本編(ロング動画/詳細条件)を遮断（Substack スクショの「This post is for paid subscribers」型ハードカットゲートに準拠。Round2 の縦グラデフェード記述は参照スクショと不整合のため撤回）。本編は遮断帯の背後に**輪郭だけうっすら**（"もっとある"の予告。中身を完全には隠さない＝威圧回避）。
- (b) ゲートブロック中央に鍵アイコン(直径28px 金1pxアウトライン円)＋文言「続きは紹介者から合言葉を聞いて開けます」。
- (c) 入力UI: 単一フィールド(`placeholder="合言葉"`)＋金アウトライン「解除する」をゲートブロック内に配置(下1/3 親指リーチ)。
- (d) エラー(navy-400): 案A と同文言。
- (e) **威圧的でない根拠**: 上半分が読めるので「拒否」でなく「もっとある」の予告。鍵は小・細線。
**unlocked 画面:**
- ゲートブロックが 250ms で解け、区切り線が消えて下半分(本編)が立ち上がる(`fade-in + translateY`)。
- ハブの 07 タイルの金鍵アイコンが**金チェック**に変わる(全体像として「開いた」を示す)。
- 表示: ショート/ロング タブ＋プラン比較(Peloton 型)＋報酬条件。

## 推奨

**案B（ハブ&ダッシュボード型）を主軸に、案Aの薄型章扉(48px)による現在地・物語性を取り込んだハイブリッドを推奨。**

根拠（形容詞でなく要件適合で）:
1. 要件＝紹介者が 1 対 1 で見せるツール。見込み客の温度・属性が毎回違うため、冒頭ハブから関心箇所へ飛べる非線形(B)が対面運用に最も適合(Genius=タイルで分岐 ＋ iOS ホーム画面=ハブに戻って別機能へ移る往復＝hub-and-spoke)。
2. 準備中が多い段階公開との適合が最良。冒頭ハブのタイルが全13＋"今後"を一望させ、準備中を「ロードマップ」として見せられる(Confirmed の"次にすること")。案C(没入)は準備中で構造が乱れやすい(帯で対処はするが2系統化)。
3. 長尺の迷子は案Aの薄型章扉＋現在地表示で補える(B の物語性の弱さを補強)。
4. 実装コスト: A=低/B=中/C=高。Next.js14＋既存トークン＋既存 `VideoPlayer`/`password` API で B ハイブリッドは現実的。C の snap/横スナップ/observer 多重はリスクが高い。

次点: スマホ単体・短時間・ビジュアル訴求最優先なら案C(読み物例外処理・写真無し面構成の確定対処込み)。
